# Эмулятор оболочки ОС

Конфигурационное управление, практическая работа 1, вариант 6.
Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
(tkinter). Работает на Python 3.10+.

## Состояние проекта

Этапы 1 (REPL), 2 (конфигурация) и 3 (VFS) выполнены.

## Возможности этапа 1

- окно с областью вывода и строкой ввода, заголовок содержит имя VFS
  (пока имя по умолчанию `vfs`);
- парсер делит ввод на команду и аргументы по пробелам;
- сообщения об ошибках: неизвестная команда, лишние аргументы;
- команды:
  - `ls [args...]` - заглушка, печатает свое имя и аргументы;
  - `cd [arg]` - заглушка, печатает свое имя и аргументы
    (больше одного аргумента - ошибка);
  - `exit` - закрывает эмулятор (с аргументами - ошибка).

## Возможности этапа 2

Параметры командной строки (все необязательные):

| параметр       | что делает                                         |
|----------------|----------------------------------------------------|
| `--vfs-path`   | путь к папке на диске, из которой грузится VFS     |
| `--prompt`     | свое приглашение к вводу, например `--prompt "> "` |
| `--log-file`   | путь к лог-файлу в формате XML                     |
| `--script`     | путь к стартовому скрипту                          |

При запуске все параметры печатаются в консоль и в окно
(строки `[debug] ...`).

Лог (XML) пополняется при каждом вызове команды, в том числе
ошибочном. Если файл уже есть, события дописываются в конец:

```
<log>
  <event>
    <datetime>2026-10-10T13:21:52</datetime>
    <command>ls</command>
    <args><arg>-l</arg></args>
    <status>ok</status>
  </event>
</log>
```

Стартовый скрипт - текстовый файл, по команде в строке. Все после `#`
(в начале строки или после пробела) - комментарий, пустые строки
пропускаются. В окне видно и ввод (с приглашением), и вывод, как будто
команды набирает пользователь. Если строка закончилась ошибкой, выводится
`script error: line N: ...`, остальные строки выполняются дальше. Если
скрипт не удалось прочитать, выводится `script error: cannot read ...`.
Если лог-файл не открылся, об этом пишется в консоль и в окно, эмулятор
работает без лога. После `exit` в скрипте окно закрывается.

Примеры скриптов лежат в `startup/`, скрипты ОС для проверки всех
параметров - в `scripts/` (`stage2_*.sh`). Каждый скрипт запускает
окно, после проверки его надо закрыть (или набрать `exit`).

## Возможности этапа 3

- источник VFS - обычная папка на диске (`--vfs-path`);
- папка целиком читается в память (файлы как байты, поэтому двоичные
  данные тоже работают), все операции идут только в памяти, на диске
  ничего не меняется и не распаковывается;
- имя VFS (имя папки) показывается в заголовке окна, без параметра
  используется `vfs` и пустая файловая система;
- ошибки загрузки показываются в окне и в консоли, эмулятор при этом
  запускается с пустой VFS:
  - `error: path not found: ...` - папки нет;
  - `error: wrong format, not a directory: ...` - указан файл;
  - `error: cannot read ...` - не удалось прочитать файл или папку;
- служебная команда `vfs-info` печатает имя VFS, число папок и файлов,
  общий размер и дерево файлов.

Примеры VFS лежат в `sample_vfs/`: `minimal` (один файл), `several`
(несколько файлов, скрытый файл и папка) и `deep` (4 уровня папок).
Скрипты ОС `scripts/stage3_*.sh` запускают эмулятор на всех вариантах
VFS, в том числе с ошибочными путями. Стартовый скрипт для всех команд
этапов 1-3: `startup/stage3_all.txt`.

## Сборка и запуск

Зависимости для запуска не нужны, нужен только tkinter
(в Linux: `sudo apt install python3-tk`).

```
python3 src/main.py      # или ./run.sh, run.bat в Windows, make run
python3 src/main.py --vfs-path sample_vfs/several --prompt "emu> " \
    --log-file logs/log.xml --script startup/stage3_all.txt
```

Тесты и проверка стиля:

```
pip install -r requirements-dev.txt
python3 -m pytest        # или make test
python3 -m flake8 --max-line-length 80 src tests   # или make lint
```

Тесты окна требуют дисплей, без него они пропускаются
(на сервере можно запустить через `xvfb-run -a python3 -m pytest`).
Файл `tests/test_style.py` проверяет правила оформления из задания:
длина строк, размер функций, число аргументов, сложность, docstring,
магические числа в сравнениях, имена по PEP8.

```
/
$ exit
```

## Структура

```
src/         исходный код (main, gui, shell, commands, logger, startup, vfs)
tests/       тесты
startup/     стартовые скрипты эмулятора
scripts/     скрипты ОС для проверки параметров и вариантов VFS
sample_vfs/  примеры VFS (minimal, several, deep)
run.sh, run.bat, Makefile   запуск
```
